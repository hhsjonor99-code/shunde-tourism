# 二、项目最终成果

《一卷顺德》V1 是一个纯前端静态网站，主要功能包括：

- 水墨长卷式首页；
- 顺德园林、水乡、美食、城市生活介绍；
- 5 条主路线；
- 2 条半日路线；
- 路线详情与时间轴；
- “为我画一卷”本地个性化推荐；
- 桌面端、平板和手机端响应式适配；
- GitHub Pages 自动部署。

需要特别说明：

> V1 不是实时调用高德 MCP 的在线智能规划系统。

高德 MCP 只在开发阶段用于：

- 查询景点；
- 获取坐标；
- 核验地点；
- 计算相邻景点距离；
- 核验步行或驾车时间。

核验结果最终写入：

```text
src/data/attractions.ts
src/data/routes.ts
```

网站部署后：

```text
用户填写偏好
→ 浏览器执行本地推荐规则
→ 从 7 条已核验路线中选择一条
→ 展示静态路线数据
```

浏览器不会实时调用：

- 高德 MCP；
- 高德 Web API；
- 在线大模型；
- Claude Code 本地配置。

# 第一部分：高德 API Key 与 MCP 配置

## 五、在高德开放平台生成 API Key

高德 API Key 不是在 ModelScope 生成，而是在高德开放平台生成。

正确地址：

https://console.amap.com/dev/key/app

### 操作步骤

1. 登录高德开放平台；
2. 进入“应用管理”或 Key 管理页面；
3. 创建一个新应用；
4. 在应用下添加 Key；
5. 根据实际用途选择合适的平台类型；
6. 保存生成的 Key；
7. 记录该 Key 对应的应用和用途。

建议命名清楚，例如：

```text
应用名称：一卷顺德学习项目
Key 名称：amap-mcp-dev
用途：Claude Code 开发阶段地图数据核验
```

### 安全注意事项

API Key 不要：

- 写进 React 前端源码；
- 写进 `VITE_*` 环境变量后打包；
- 写进 README；
- 提交到 GitHub；
- 截图时完整展示；
- 发到群聊或公开文档。

如果 Key 泄露：

1. 立即进入高德控制台；
2. 删除或停用旧 Key；
3. 重新生成新 Key；
4. 更新本地配置；
5. 检查 Git 历史中是否已经提交。

## 六、从 ModelScope 获取高德地图 MCP 配置

打开：

https://www.modelscope.cn/mcp/servers/@amap/amap-maps

该页面提供高德地图 MCP 服务配置。

MCP 的作用是让 Claude Code 可以调用外部地图工具，而不是只依赖模型记忆。

可能得到类似配置：

```json
{
  "mcpServers": {
    "amap-maps": {
      "type": "sse",
      "url": "https://某个服务地址/sse"
    }
  }
}
```

说明：

- `amap-maps`：MCP 服务名称；
- `type: "sse"`：远程连接方式；
- `url`：ModelScope 生成的服务地址。

### 需要区分两个概念

| 内容 | 在哪里获得 | 作用 |
|---|---|---|
| 高德 API Key | 高德开放平台 | 授权使用高德开放能力 |
| MCP 服务配置 | ModelScope MCP 广场 | 让 Claude Code 连接地图 MCP 服务 |

两者不是同一个东西。

### 当前关于 SSE 的注意事项

Claude Code 官方文档目前提示：

> SSE 传输方式已被标记为 deprecated；如果服务方提供 HTTP MCP，应优先使用 HTTP。

但如果 ModelScope 当前给出的仍是 SSE 配置，可以继续按其页面提供的配置使用。以后 ModelScope 如果改为 HTTP，应优先换成新的 HTTP 地址。

## 七、在 Claude Code 中配置高德 MCP

有两种主要方式：

1. 使用 Claude Code 命令配置；
2. 手动编辑 JSON 配置。

推荐优先使用命令行，因为更不容易破坏配置文件。

---

### 方式 A：使用 Claude Code 命令添加

打开 PowerShell、CMD 或 Git Bash。

先确认 Claude Code 可用：

```bash
claude --version
```

添加 SSE MCP：

```bash
claude mcp add --transport sse amap-maps --scope user "你的 ModelScope SSE 地址"
```

示例结构：

```bash
claude mcp add --transport sse amap-maps --scope user "https://example.com/xxxx/sse"
```

这里使用：

```text
--scope user
```

表示该 MCP 对当前用户的所有 Claude Code 项目可用。

如果只想给当前项目使用，可以在项目根目录执行：

```bash
claude mcp add --transport sse amap-maps --scope project "你的 ModelScope SSE 地址"
```

不过需要注意：

> 项目级配置通常会写入项目根目录的 `.mcp.json`，如果 URL 中包含敏感标识，不要提交到 GitHub。

因此，个人使用时更推荐：

```text
user scope
```

如果命令参数发生变化，可先执行：

```bash
claude mcp add --help
```

查看本机当前 Claude Code 版本的准确语法。

---

### 方式 B：使用 JSON 配置添加

#### 用户级配置位置

Claude Code 用户级和本地作用域的 MCP 配置通常存储在：

```text
~/.claude.json
```

Windows 下可理解为：

```text
C:\Users\你的用户名\.claude.json
```

可以使用 CMD 打开：

```cmd
notepad "%USERPROFILE%\.claude.json"
```

注意：

> 不要直接覆盖整个 `.claude.json`。该文件还可能包含登录状态、权限、项目状态等内容，只应合并 `mcpServers` 节点。

配置结构示例：

```json
{
  "mcpServers": {
    "amap-maps": {
      "type": "sse",
      "url": "你的 ModelScope SSE 地址"
    }
  }
}
```

如果原文件已经有其他内容，应类似这样合并：

```json
{
  "已有配置": "保留",
  "mcpServers": {
    "已有服务": {
      "type": "http",
      "url": "https://example.com/mcp"
    },
    "amap-maps": {
      "type": "sse",
      "url": "你的 ModelScope SSE 地址"
    }
  }
}
```

#### 项目级配置位置

项目共享 MCP 配置可放在项目根目录：

```text
.mcp.json
```

示例：

```json
{
  "mcpServers": {
    "amap-maps": {
      "type": "sse",
      "url": "你的服务地址"
    }
  }
}
```

但对于带私人标识的服务地址，不建议提交。

可以将其加入：

```gitignore
.mcp.json
```

或者改用用户级配置。

## 八、验证 MCP 是否配置成功

### 1. 在终端查看 MCP 列表

```bash
claude mcp list
```

查看单个服务：

```bash
claude mcp get amap-maps
```

正常时应能看到：

- 名称：`amap-maps`；
- 类型：`sse` 或 `http`；
- URL；
- 连接或可用状态。

### 2. 启动 Claude Code

进入项目目录：

```cmd
cd /d "E:\Coding\claud code\shundeTourism"
claude
```

在 Claude Code 会话中输入：

```text
/mcp
```

检查 `amap-maps` 是否显示 Connected。

### 3. 做实际查询测试

向 Claude Code 发出：

```text
请使用高德地图 MCP 查询清晖园的位置和地址。
```

再测试路线：

```text
请使用高德地图 MCP 查询清晖园到华盖路步行街的步行距离和时间。
```

### 4. 确认 Claude 真的调用了 MCP

不要只看回答内容，要看 Claude Code 是否显示：

- 调用了 `amap-maps` 工具；
- 返回地点信息；
- 返回路线距离和时间；
- 没有只凭模型记忆回答。

## 十、MCP 常见问题排查

### 问题 1：MCP 显示未连接

依次检查：

1. URL 是否完整；
2. JSON 是否缺少逗号或括号；
3. `type` 是否正确；
4. 网络和代理是否可访问；
5. Claude Code 是否需要重启；
6. ModelScope 服务是否仍有效；
7. 是否达到额度或调用上限。

执行：

```bash
claude mcp list
claude mcp get amap-maps
```

然后在 Claude Code 中执行：

```text
/mcp
```

---

### 问题 2：项目级 MCP 显示 Pending approval

项目级 `.mcp.json` 可能需要信任确认。

处理方法：

1. 在项目目录运行 `claude`；
2. 接受工作区信任；
3. 审核 MCP 配置；
4. 同意启用该服务。

不要直接信任来历不明仓库中的 MCP 配置。

---

### 问题 3：Claude 能回答，但没有调用 MCP

提示词中明确要求：

```text
必须调用高德地图 MCP，不要根据模型记忆回答。
请列出本次调用的 MCP 工具和返回结果。
```

---

### 问题 4：SSE 以后不能用了

如果 ModelScope 后续提供 HTTP MCP：

```json
{
  "type": "http",
  "url": "https://example.com/mcp"
}
```

可改用：

```bash
claude mcp add --transport http amap-maps --scope user "HTTP 地址"
```

远程 MCP 当前优先使用 HTTP；SSE 仅在服务方仍只提供 SSE 时继续使用。

---

### 问题 5：配置会不会被部署到网页

不会。

Claude Code 本地配置：

```text
~/.claude.json
.mcp.json
```

与 Vite 构建后的网页不是同一个运行环境。

GitHub Pages 中的 React 网站无法读取你电脑里的 Claude Code MCP 配置。

# 第三部分：高德 MCP 数据核验

## 十五、先核验数据，再开发页面

本项目使用 MCP 核验：

- 14 个地点；
- 5 条主路线；
- 2 条半日路线；
- 景点之间的路段；
- 每段距离；
- 每段时间；
- 步行或驾车方式。

核验结果保存到：

```text
src/data/attractions.ts
src/data/routes.ts
docs/mcp-verification.md
```

推荐让 Claude 输出：

- 调用的 MCP 工具；
- 查询参数；
- 返回地点；
- 坐标；
- 距离；
- 时间；
- 数据核验日期；
- 未核验字段。

不要让模型自行估算或编造数据。

---

## 十六、路线统计口径

路线总距离只统计：

> 相邻景点之间已核验的路段。

不包括：

- 用户出发地到首站；
- 住宿接驳；
- 候车；
- 停车；
- 景区内部游览；
- 未核验的公交时间；
- 跨日住宿接驳。

类型中明确记录：

```ts
distanceScope: 'between-stops-only'

timeBasis:
  | 'amap-driving'
  | 'amap-walking'
  | 'mixed-driving-walking'
  | 'not-available'
```

## 二十、为什么要分阶段执行

一次完成大型任务容易出现：

- 忘记约束；
- 自行扩大范围；
- UI 风格漂移；
- 修改核验数据；

# 第五部分：测试、排错和 Token 中断

# 十一、最终总结

本项目跑通了一套完整的 AI 协作开发方法：

```text
业务想法
→ 高德生成 API Key
→ ModelScope 获取 MCP 配置
→ Claude Code 连接地图工具
→ MCP 核验真实数据
→ UI Prompt 选择风格
→ ChatGPT 完成设计
→ Claude Code 规划
→ 分阶段开发
→ Git 版本管理
→ 浏览器验收
→ GitHub Actions
→ GitHub Pages 上线
```

最值得长期保留的原则：

> 先确定目标，再选择工具。  
> 先完成规划，再开始编码。  
> MCP 用来获取和核验事实，不能替代产品设计。  
> 先完成静态版本，再增加实时能力。  
> 每个阶段都要人工验收，每个阶段都要 Git commit。  
> AI 可以帮助开发，但最终判断必须由人完成。
